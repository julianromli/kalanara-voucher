# React Improvement Audit

Audit target: `b94c4ae`
Scope: production application code only; read-only review plus React Doctor 0.9.14 evidence.

## Executive assessment

React Doctor scored the repository **34/100 (Critical)**: 349 de-duplicated diagnostics across 100 affected files (11 errors, 338 warnings; 441 source files reported). Category counts are Bugs 64, Performance 66, Accessibility 159, Security 7, and Maintainability 53. The raw count is inflated by reference code and low-impact repetition, but the score still reflects real high-leverage risks in payment correctness, privileged server actions, checkout accessibility, and data-loading architecture.

The highest priority is not cosmetic React cleanup. It is to make privileged mutations unreachable from untrusted Server Action calls, make payment transitions monotonic and fulfillment idempotent, constrain public payment creation, and stop leaking the order capability token to global analytics.

## Stack and leverage map

- **Runtime:** Next.js 16.0.10 App Router/RSC, React 19.2, strict TypeScript, Tailwind 4.
- **State/data:** Zustand 5 for cart state plus Auth, Store, and Toast contexts; Supabase SSR and service-role clients; no React Compiler or TanStack Query.
- **UI/integrations:** React Hook Form, Radix/shadcn, TanStack Table, UploadThing, Scalev, jsPDF/qrcode/jsQR.
- **Highest leverage:** public checkout and payment callback paths, webhook/reconciliation state transitions, service-role Server Actions, voucher fulfillment and delivery.
- **Broad fan-out:** root providers, root navbar/settings queries, Meta Pixel, public checkout bundles.
- **Growth-sensitive:** admin purchases/vouchers/reviews and dashboard queries that currently load full histories.
- **Important but bounded:** verify/review flows, QR camera lifecycle, admin control names.
- **Low leverage:** repeated transition utilities and cold-page component-size warnings unless addressed while consolidating checkout domain code.

Context7 could not independently supply the current Next.js security recipe because its monthly quota was exhausted. React Doctor's package scanner did verify CVE-2026-23870 against installed `next@16.0.10` and reports Next 16.2.6 as the minimum patched release.

## Missed opportunities

- **Domain boundaries and streaming:** add checkout/voucher error boundaries and granular Suspense around independently failing remote data; confirm placement with real slow/failure traces so boundaries do not create layout churn.
- **Interaction-triggered imports:** load PDF/QR implementation only on download/scanner activation, then compare route JS and interaction delay before/after.
- **Evidence-led optimistic UI:** admin voucher/service mutations already use optimistic state in places. Expand it only where latency telemetry or user testing shows a wait problem, with rollback and duplicate-submission protection.
- **Narrow client ownership:** split Toast actions from rendered state and prefer server-first data/config flow for checkout/navbar; use Profiler/network evidence to choose boundaries rather than adding memoization indiscriminately.

## Rejected findings and scanner noise

- `docs/**`, including `docs/vite/**` and UI-reference templates, is non-production reference material and is excluded from implementation findings.
- Array-index keys observed in static/stateless presentation lists do not carry reorderable component state and were rejected.
- Cart/auth/theme hydration guards are intentional persistence/browser-boundary handling; they should not be removed mechanically.
- Object URL cleanup already exists in service-image previews and PDF download paths.
- The suggested Set optimization in the payment-options fallback operates on a tiny fixed list and is not useful.
- Locale formatting flagged during initial hydration is absent from a server/client mismatch path or occurs in client-only output; no broad rewrite is justified.
- Historical permissive RLS migrations are superseded by later policy migrations; deployment state should be verified, but old migration text is not itself an active defect.
- The jsPDF advisory is not currently exploitable through the browser-only constant/data-URL flow reviewed here; dependency maintenance remains prudent, but it is not a HIGH security finding.
- shadcn primitives intentionally use `outline-none` together with `focus-visible:ring-*`; those controls retain visible focus and are not violations.
- No deliberate React Doctor suppressions or config opt-outs were found; there is no accepted tradeoff to override.

## Audit constraints

This document does not claim runtime proof for races, provider ordering, or bundle cost. Those findings require concurrency tests, request traces, and bundle analysis during execution. No source, configuration, dependency, or lockfile was changed.
